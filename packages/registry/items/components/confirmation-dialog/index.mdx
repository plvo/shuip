With `ConfirmationDialog`, the same result in a clean, reusable component. Clicking the confirm button calls `onConfirm`, then closes the dialog. Set `labelCancelButton` to add a cancel button next to it:

```tsx	
<ConfirmationDialog
  trigger={<Button variant="destructive">Delete</Button>}
  title="Are you sure?"
  description="This action cannot be undone. This will permanently delete the item."
  labelConfirmButton="Delete"
  labelCancelButton="Cancel"
  onConfirm={handleDelete}
/>
```

## Async confirmation

When `onConfirm` returns a promise, the dialog waits for it:

- the confirm button is disabled and shows a spinner, so a second click cannot start the action twice;
- the dialog closes when the promise resolves;
- the dialog stays open and the button is enabled again when it rejects. The rejection is not logged or rethrown by the component: show the error yourself, for example in the `description`.

```tsx
<ConfirmationDialog
  trigger={<Button variant="destructive">Delete Account</Button>}
  title="Delete Account"
  description="This will permanently delete your account and all associated data."
  labelConfirmButton="Delete Account"
  labelCancelButton="Cancel"
  onConfirm={() => deleteAccount()}
/>
```

A synchronous `onConfirm` closes the dialog right after it returns, as before. Closing the dialog while the promise is pending does not cancel the work: the promise keeps running and the confirm button stays pending until it settles.

<BaseOnly base="base">

The dialog closes through the Base UI `actionsRef`, so `onOpenChange` receives the `imperative-action` reason when a promise resolves.

</BaseOnly>

## Common use cases

### Delete confirmation

```tsx	
<ConfirmationDialog
  trigger={<Button variant="destructive">Delete Account</Button>}
  title="Delete Account"
  description="This will permanently delete your account and all associated data. This action cannot be undone."
  labelConfirmButton="Delete Account"
  labelCancelButton="Cancel"
  onConfirm={() => deleteAccount()}
/>
```

### Save confirmation

```tsx	
<ConfirmationDialog
  trigger={<Button>Save Changes</Button>}
  title="Save Changes"
  description="Are you sure you want to save these changes?"
  labelConfirmButton="Save"
  onConfirm={() => saveChanges()}
/>
```

### Custom trigger with icon

```tsx	  
<ConfirmationDialog
  trigger={
    <Button variant="ghost" size="icon">
      <Trash2 className="size-4" />
    </Button>
  }
  title="Delete Item"
  description="This item will be permanently removed."
  labelConfirmButton="Delete"
  onConfirm={() => deleteItem(id)}
/>
```

### Controlled dialog

Pass `open` and `onOpenChange` to open the dialog from your own state, without a `trigger`. The dialog still closes after `onConfirm`, and when an async `onConfirm` resolves, by calling `onOpenChange(false)`:

```tsx
const [open, setOpen] = useState(false);

<ConfirmationDialog
  open={open}
  onOpenChange={setOpen}
  title="Delete Item"
  description="This item will be permanently removed."
  labelConfirmButton="Delete"
  onConfirm={() => deleteItem(id)}
/>
```
